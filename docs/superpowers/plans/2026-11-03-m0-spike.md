# Milestone 0: Go/No-Go Spike Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove on a real AYN Thor that the pieces work:
- an xNVSE plugin loads under GameNative + FEXCore;
- it serves a loopback WebSocket an Android app on the bottom screen can reach;
- its main loop keeps running when the bottom screen is tapped;
- it can read HP, Hardcore, TTW world flags, UI colors and the worldspace, and can run one equip.

**Architecture:** A C++ xNVSE plugin. Portable net/protocol code is unit-tested on Linux (g++) and Windows
(MSVC). A Winsock server thread exchanges messages with the game main thread (`kMessage_MainGameLoop`) through
locked queues. A minimal Kotlin/Compose app connects over `ws://127.0.0.1:7960`, shows live values plus a
"main loop alive" indicator, and copies a results report to the clipboard. A Python mock server lets the app be
exercised without the game. CI on GitHub Actions builds both and publishes a pre-release.

**Tech Stack:** C++20, CMake ≥3.25, MSVC v143 Win32 `/MT`, xNVSE headers (pinned tag), nlohmann/json 3.11.3,
doctest 2.4.11 · Kotlin 2.0.21, AGP 8.7.3, Gradle 8.10.2, Compose BOM 2024.12.01, OkHttp 4.12.0,
kotlinx.serialization 1.7.3, JUnit 4.13.2 · Python 3.12 + `websockets` 13.1 + pytest 8.3 · Docker
(`eclipse-temurin:17-jdk` + Android cmdline-tools, platform 35, build-tools 35.0.0).

**Spec:** `docs/superpowers/specs/2026-11-03-ttw-dualscreen-design.md` (§3, §6.1–6.2, §6.6, §7, §10 milestone 0, §12).
Research: `docs/superpowers/specs/research/nvse-plugin.md` (§1, §3, §5, §8 are the reference for engine access).

## Global Constraints
- The server binds **`127.0.0.1` only**. Default port **7960**. Never 7786–7788, 8765, 27000 or 28000.
- **No game code patches or hooks.** Engine reads plus the xNVSE console interface only.
- **Never keep `TESForm*`/`TESObjectREFR*` across frames or loads.** Re-resolve each use. Drop state on
  PreLoadGame, ExitToMainMenu and NewGame.
- All game access happens on the main thread inside the `kMessage_MainGameLoop` handler. The network thread
  never touches game memory.
- Use std::mutex/atomics only for cross-thread state. No lock-free structures.
- Plugin refuses to load unless the runtime is FNV 1.4.0.525. It logs why to
  `Data\NVSE\Plugins\ttw_dualscreen.log`.
- No Bethesda/TTW assets in the repo or the builds. License **GPL-3.0-or-later**. Third-party notices go in
  `NOTICE`.
- Android: `minSdk 30`, `targetSdk 35`, package **`com.ttwdualscreen.app`**. Cleartext only to
  `127.0.0.1`/`localhost`.
- The app **never starts an activity on the game display**.
- Git author for this repo: `ghost <t.j.adams06@gmail.com>`. Commit messages end with the attribution lines
  from the session.

## Review Focus
1. **Main loop stalls while the socket stays up** (bottom screen focused): the app must still show "socket
   alive", and must clearly flag "main loop STALLED" once more than 1 s passes without a `state` frame. Covered
   by Task 7's `StallDetectorTest`.
2. **Client disconnects mid-frame, or two clients connect:** the server must not crash or block the game
   thread. A second client is accepted, or refused with a close frame, and the game thread never waits on a
   socket. Covered by Task 4's `server_two_clients_and_abrupt_close` test.
3. **A command arrives before a save is loaded** (main menu): return
   `{"ok":false,"error":"no save loaded"}`, not a crash or a silent drop. Covered by Task 5's dispatcher unit
   test using a fake game.
4. **Oversized or malformed frames** (bad JSON, 10 MB payload, unmasked client frame): close with code 1002 or
   1009 and keep the server running. Covered by Task 2/3 tests.
5. **Missing TTW** (plain FNV): `bInDCWasteland`/`bInNVWasteland` are `null` and `ttw:false`, and nothing
   throws. Covered by Task 5's `globals_absent_reports_null` test.

### Task 2: Portable WebSocket core (SHA-1, base64, handshake, framing)

**Files:** Create `plugin/CMakeLists.txt` (target `ttwds_core` static lib + `ttwds_tests`; fetch doctest and
nlohmann via FetchContent at the pinned tags), `plugin/src/net/*`, `plugin/tests/test_net.cpp`,

**Interfaces — Produces:**
- `std::array<uint8_t,20> sha1(std::string_view)` and `std::string base64(std::span<const uint8_t>)`
- `std::optional<std::string> ws_accept_response(std::string_view httpRequest)`: returns the full `101`
  response, or nullopt when not a valid upgrade (missing `Sec-WebSocket-Key`, not GET, no `Upgrade: websocket`).
- `struct WsFrame { uint8_t opcode; bool fin; std::string payload; };`

- `DecodeStatus ws_decode(std::string& buf, WsFrame& out, size_t maxPayload = 1<<20)`: consumes from `buf`
  on Ok, and **requires the client mask bit** (otherwise ProtocolError).
- `std::string ws_encode(uint8_t opcode, std::string_view payload)`: server frames, unmasked, 7/16/64-bit
  lengths.

**Interfaces:**
- Consumes: Task 2/3 functions.
- Produces:
  - `class WsServer { public: bool start(const std::string& bind, uint16_t port, std::function<Inbound(std::string_view)> classify); void stop(); bool pollCommand(PendingCommand& out); void sendToAll(std::string json); bool hasSpikeSubscriber(int& rateHz) const; };`
